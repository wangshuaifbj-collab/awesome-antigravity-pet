# 宠物请求广场点赞试验

这个为期一周的试验用于先验证真实需求，再决定是否建设独立的请求广场或增加统计服务。点赞和认领继续留在 GitHub，因此不会新增实时 Worker 请求。

> 实施更新（2026 年 7 月 29 日）：网站制作需求广场已经获准提前建设。GitHub Issue 继续作为请求与认领的事实来源；网站读取有界静态快照，并提供匿名、可撤销的“我也想要”支持和仅保存在本机的进度关注。

## 试验周期

- 开始：2026 年 7 月 28 日
- 结束：2026 年 8 月 4 日 10:00 UTC
- 试验请求：#69、#62、#50、#47、#45
- 点赞：在 Issue 的试验评论上添加 👍 reaction
- 认领：贡献者评论说明愿意制作；维护者确认后添加 `status: in-progress`

每个 GitHub 账号在一个 Issue 上最多产生一个可见 reaction。点赞只代表社区兴趣，不代表请求已经受理或承诺交付。同一角色的已有宠物和请求应该互相链接，而不是隐藏；如果新请求明确要求不同作者独立制作、并且能说明差异，它仍然可以保留。

## 快照与复盘

试验结束后记录一次最终快照，不做实时聚合。

复盘以下指标：

- 每个请求的点赞数以及点赞是否过度集中
- 新增认领数以及点赞到认领的关系
- 试验中发现的重复请求
- 维护成本和认领状态是否清晰

第一版静态请求广场已按上述边界落地：构建时读取有界 GitHub 快照、复用现有状态标签、普通页面只读取静态统计文件，不持续轮询 Worker。试验数据仍用于后续复盘排序、认领和社区转化效果。
